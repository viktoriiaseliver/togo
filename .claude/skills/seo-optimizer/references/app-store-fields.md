# Поля витрины App Store: лимиты и что с ними делать

Лимиты Apple, счёт в **символах** (не байтах — кириллица считается
как есть). Файлы лежат в `fastlane/metadata/ru/`.

| Файл | Поле в App Store Connect | Лимит | В поиске |
|---|---|---|---|
| `name.txt` | Name | 30 | **да** |
| `subtitle.txt` | Subtitle | 30 | **да** |
| `keywords.txt` | Keywords | 100 | **да** |
| `description.txt` | Description | 4000 | нет |
| `promotional_text.txt` | Promotional Text | 170 | нет |
| `release_notes.txt` | What's New | 4000 | нет |
| `privacy_url.txt` | Privacy Policy URL | — | обязательно для внешнего теста |
| `support_url.txt` | Support URL | — | обязательно для ревью |
| `review_notes.txt` | App Review Notes | 4000 | нет |
| `testflight_description.txt` | Beta App Description | 4000 | нет |
| `testflight_whats_new.txt` | Beta Build What to Test | 4000 | нет |

Проверить длину всех коротких полей разом:

```sh
for f in name subtitle keywords promotional_text; do
  printf '%-18s %s\n' "$f" "$(python3 -c "import sys;print(len(open(sys.argv[1],encoding='utf-8').read().strip()))" fastlane/metadata/ru/$f.txt)"
done
```

## Индекс поиска

Apple склеивает `name` + `subtitle` + `keywords` + название разработчика
+ названия внутренних покупок в один набор токенов. Отсюда следствия:

* **Повтор бесполезен.** Слово из `name` не даёт ничего, стоя ещё и
  в `keywords`, — только съедает символы из ста.
* **Комбинации собираются сами.** Есть «собака» и «дневник» — запрос
  «дневник собаки» находит. Писать словосочетание целиком не нужно.
* **Пробелы после запятых — потерянные символы.** `а,б,в`, не `а, б, в`.
* **Единственное число, именительный падеж.** Морфологию Apple
  разбирает сам; «собаки», «собакам» — выброшенные символы.
* **Названия внутренних покупок тоже индексируются** — они в
  `subscriptions.json`, их стоит считать частью ASO.

## Чего нельзя

* Названия чужих приложений и брендов в `keywords` — отказ по 2.3.7.
* Описание функций, которых нет, — 2.3.1. Проверять по коду, а не по памяти.
* «Лучшее», «№1», «топ» без подтверждения — 2.3.
* Слова «бета», «тест», «demo» в витрине релиза.
* Медицинские утверждения. Приложение — дневник, не диагност; в текстах
  это должно быть видно.

## Промо-текст — единственное, что меняется без релиза

`promotional_text` (170) обновляется в App Store Connect отдельно от
сборки. Там держат то, что зависит от времени: «в этой версии…»,
сезонное, ответ на частый вопрос. В `description` такого быть не должно —
его правка требует новой версии.

## Порядок в описании

Первые три строки видны без «ещё» — в них должно быть сказано всё
главное. Дальше блоки заголовками капслоком: так их видно при
пролистывании. Последняя строка — про приватность: «Всё считается
на телефоне. Аккаунт не нужен.» — это то, из-за чего ставят.
