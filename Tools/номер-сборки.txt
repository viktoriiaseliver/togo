# Поднято 274 → 275 решением Виктории 09.10.2026 («готовь 275»),
# передано менеджером смены. Замер ASC МОИМ запросом перед правкой,
# а не пересказом:
#
#   GET /v1/builds?filter[app]=6805876636&sort=-version&limit=6
#   273 VALID · 271 · 258 · 256 · 248 · 216      новейший занятый 273
#
# 275 свободен, и 274 тоже был свободен — то есть НОМЕР 274 НЕ УЕДЕТ
# НИКОГДА. Это решение, а не побочный эффект: номера растут и не
# возвращаются, пропуск безвреден, но он должен быть назван, иначе
# следующий прочтёт дыру в последовательности как потерянную сборку.
# Рядом такие же пропуски, уже случившиеся: 272 и 274 — в ASC скачок
# 271 → 273.
#
# Почему файлом, а не `git rev-list --count HEAD`.
#
# Счёт коммитов рос быстрее загрузок: 07.10.2026 в ASC лежала сборка
# 271, а счёт дошёл до 506. Собери по счёту — и номер прыгнет на 235
# вперёд необратимо: номера обязаны расти, и вернуться к 274 после 506
# нельзя уже никогда.
#
# Решение Виктории 07.10.2026: держать непрерывность, собирать 273.
# Отсюда и форма записи: номер — это РЕШЕНИЕ, а не производная от
# истории. Производная выглядела надёжнее («git считает это надёжнее
# человека» стояло в upload_testflight.sh) и измеряла не ту величину —
# количество нашей работы вместо количества отданных сборок.
#
# Три копии одного допущения жили в трёх файлах, и третья была сторожем,
# который ПОТРЕБОВАЛ БЫ неверный номер: archive_fingerprint.sh сравнивал
# номер архива со счётом коммитов и сказал бы «архив не от этого
# коммита» про верный архив. Вторая копия переживает правку первой —
# за это уже заплачено в тот же день условием заморозки схемы, которое
# жило в двух местах.
#
# Поднимать РУКОЙ перед каждой загрузкой, на единицу. Забыли — ASC
# откажет громко: номер уже занят. Это отказ, а не молчание, и потому
# допустимая цена; прыжок на 235 молчит и необратим.
#
# Перед правкой — спросить ASC, что там сейчас новее всего:
#   source ~/Projects/Gamut/.env.asc
#   GET /v1/builds?filter[app]=6805876636&sort=-version&limit=1
# Номер в файле обязан быть больше. Ответ ASC — не предсказание исхода
# (у нас записано, что ни один код ответа его не предсказывает), но
# на вопрос «какое число уже занято» он отвечает прямо.
#
# Дописано `togo-08` по приглашению: короче, чем объяснение выше,
# и объясняет его.
#
# Прежняя редакция этого номера жила в шапке `docs/что-тестировать.md`
# как «равен числу коммитов, на момент написания 500». Я тогда заметил
# частное — что номер нельзя записать в имя файла, потому что коммит
# файла номер сдвигает, — и сделал из этого неверный вывод: «номер
# не писать». Верный вывод был другой:
#
#   Номер сборки — РЕШЕНИЕ, а не производная от истории. Решение
#   записывается; производную от истории внутрь той же истории
#   записать нельзя — запись меняет то, из чего она выведена.
#
# Поэтому дело не в имени файла и не в прыжке на 235: прыжок —
# последствие, а причина в том, что величину взяли не той формы.
# Производная выглядела надёжнее именно потому, что её «считает git»,
# и мерила при этом количество нашей работы вместо количества
# отданных сборок.
