# Архитектура

Одна цель: чтобы источник каждой вещи был ровно один и его было видно.
Оформление приходит из `tokens.json`, структура проекта — из
`Tools/generate_project.py`, смысл — из моделей и чистой логики.

## Слои

```
       ┌──────────────────────────────────────────────┐
       │  Togo/Features · экраны                      │  знают про домен и про TG*
       ├──────────────────────────────────────────────┤
       │  Togo/DesignSystem · TG*-компоненты, тема    │  знают про токены, не знают про домен
       ├──────────────────────────────────────────────┤
       │  TogoShared/Domain · логика без UI           │  ничего не знает про SwiftUI
       │  TogoShared/Models · SwiftData               │
       │  TogoShared/Generated · Token.*              │
       └──────────────────────────────────────────────┘
                    ▲                        ▲
              Togo (app)              TogoWidgets (extension)
```

`TogoShared` подключён к обоим таргетам одной synchronized-группой —
копий общего кода в репозитории нет.

## Правила зависимостей

* **Домен не знает про цвет.** `SkillStatus` — это состояние обучения,
  а не оттенок. Всё, что превращает домен в оформление, лежит одним файлом
  в `Togo/DesignSystem/DomainStyle.swift`. Благодаря этому логику можно
  звать из тестов и виджета, а палитру менять, не трогая модели.
* **Экран не знает про сырые значения.** В `Togo/Features` нет ни одного
  hex, ни одного «магического» отступа: только `Token.*` и `TG*`.
* **Компонент не знает про экран.** `TGCard` не в курсе, что внутри —
  таймлайн или список семьи. Содержимое приходит слотом.
* **Чистая логика помечена `nonisolated`.** `VerdictEngine`, `Diary`, `Fmt`,
  `Token` работают вне главного актора: это позволяет виджету и тестам
  считать то же самое, что и приложение.

## Наследование темы

`Theme` лежит в окружении SwiftUI. Родитель кладёт туда свою поверхность,
дочерние компоненты её читают:

```swift
TGCard {            // кладёт .card в окружение
    TGTile { … }    // видит, что стоит на карточке, и берёт .sunken
}
```

Это тот же механизм, что и в Figma, где компонент берёт заливку от фрейма,
в который вложен. Поэтому компонент можно перенести на другой экран, и он
останется правильным без единого аргумента.

## Состояние

| Что                            | Где живёт                     | Почему там                                  |
|--------------------------------|-------------------------------|---------------------------------------------|
| Записи, собака, семья, схемы   | SwiftData в App Group         | нужны виджету и переживают перезапуск       |
| Роль, эпизод, идущий выход     | `AppState` (`@Observable`)    | относится к сеансу, а не к данным            |
| Час брифа, тихие часы, отклик  | `Settings` → `UserDefaults`   | настройки человека, не собаки                |
| Подписка                       | `SubscriptionStore` + StoreKit| источник правды у Apple, кэш в памяти        |
| Снимок для виджета             | `WidgetBridge` в App Group    | виджет не должен ходить в базу               |
| Журнал действий                | `usage.jsonl` в документах    | нужен человеку и снимается с телефона        |

Четыре флага из макета — лечение, поездка, эпизод, роль — не переключаются
руками с главного экрана. Лечение включается в профиле, поездка датой,
эпизод событием, роль приглашением.

## Поток данных на главном экране

```
SwiftData → Dog.events ─┬─→ Diary.signals ─→ VerdictEngine ─→ NeedVerdict
                        ├─→ Diary.onDay    ─→ DayTimeline
                        ├─→ Diary.summary  ─→ строка «ел и пил»
                        └─→ LiveActivityController.publishSnapshot → WidgetBridge → виджет
```

Виджет и приложение считают вердикт по одному коду, поэтому разойтись
не могут.

## Журнал действий

`UsageLog` — то, что человек делал, и чем это кончилось; `UsageReport` —
то, что из этого следует. Разделены намеренно: первое трогает диск,
второе — чистая функция над списком действий, поэтому проверяется
тестами целиком и не требует ни файла, ни базы.

```
экраны ──.usageScreen(_:)──┐
EventLog ──────────────────┼─→ UsageLog.note ─→ usage.jsonl ─→ UsageReport ─→ экран «Журнал действий»
AppState, DoseScheduler ───┘                                        │
                                                                    └─→ трения: что чинить
```

Три правила:

* **Одна дверь.** Отметка ставится там, где живёт само действие, —
  в `EventLog`, в состоянии сессии, в `DoseScheduler`. Звать из экранов
  забыли бы ровно там, где важнее всего.
* **Закрытый словарь.** Экраны и действия — перечисления, а не строки.
  Свободная строка рано или поздно принесла бы в журнал кличку собаки.
* **Не на главном потоке.** Запись уходит в свою очередь, чтение и разбор
  журнала на экране — в отдельную задачу.

## Генерация

```
DesignTokens/tokens.json
   ├─ Tools/generate_tokens.py → TogoShared/Generated/Tokens.generated.swift
   ├─                          → DesignTokens/build/tokens.css        (веб-макет)
   └─                          → DesignTokens/build/figma-variables.json (Figma)

Tools/generate_project.py → Togo.xcodeproj + общая схема
```

CI проверяет, что сгенерированное совпадает с источником (`make tokens-check`).
Если кто-то поправил Swift-токены руками, сборка падает.

## Тесты

* `TogoTests` — чистая логика: вердикт, выборки, занятие, дозы, поездка,
  форматирование. Плюс `DesignTokenTests`, который меряет контраст токенов
  и размеры целей нажатия — эти тесты уже дважды поймали настоящие ошибки.
* `TogoUITests` — дымовые: главный экран, четыре вкладки, вердикт, запись
  еды, обязательные разделы настроек. Запускаются с флагом `-UITesting`
  на чистой базе в памяти с демо-собакой. С этим же флагом молчит журнал
  действий: робот, нажимающий всё подряд, наполнял бы его действиями,
  которых человек не делал.
