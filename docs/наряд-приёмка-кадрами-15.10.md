```

```

Положен по слову менеджера при закрытии смены: потерянная работа
дороже объявленного непроверенного. **Граница объявлена в самом

```bash
git worktree add /tmp/togo-<сессия> <коммит>
cd /tmp/togo-<сессия>

  -destination "platform=iOS Simulator,id=$(python3 Tools/ci_simulator.py | tail -1)" \
  -derivedDataPath /tmp/togo-<сессия>/dd  build-for-testing
```

**Отдельным заходом, до любого прогона.** `xcodebuild` собирает
**всю схему**, и `-only-testing` от несобирающейся сюиты не спасает:
чужой прогон умрёт на ней и будет разобран как собственный дефект.
За смену это окупилось шесть раз — шесть чужих сюит собрались моими
заходами и ни одна не стала потерянным прогоном.

Если упадёт — чинить, а не объяснять: это мой файл и мой долг.

### НО СНАЧАЛА ПОСМОТРИ, ЧЕЙ ФАЙЛ В ОШИБКЕ

**Моё объявление «не собирался ни разу» делает мой файл первым
подозреваемым, и это ловушка.** В конце смены `projects-c7` померил
на дереве поломку, к моему файлу отношения не имеющую:

```
TGScaffolds.swift:125  error: no exact matches in call to initializer
                       подпись TGSheet сменили на `Надпись`,
                       внутреннюю перегрузку не поправили
```

**На вершине `64771e8` этой поломки нет** — `Надпись`
в `TGScaffolds.swift` ноль вхождений, обе подписи (`:25` и `:113`)
`LocalizedStringKey`, согласованы.

> **ПОПРАВКА К ПЕРВОЙ РЕДАКЦИИ ЭТОГО ПУНКТА, и она важнее самого
> пункта.** Я написал «жила между коммитами и была починена,
> вероятнее всего в `a2fd160`». **Ложно**, и ложно в ту сторону,
> которая отправляет следующего искать починку, которой нет,
> и решить, что `TGSheet` переведён на `Надпись`.

Замер (мой, после того как `projects-c7` опроверг моё объяснение
своим):

```
git log -S 'Надпись' -- …/TGScaffolds.swift     0 за ВСЮ историю файла
КОНТРОЛЬ: то же по Togo/DesignSystem            a2fd160 и 956c6cd → -S работает
a2fd160 тронул                                  Подпись.swift И ТОЛЬКО ЕГО
```

**Слова `Надпись` в этом файле не было ни в одном коммите.** Значит
поломка пришла из **незакоммиченной** правки в общем дереве, которая
потом из дерева исчезла.

> По правилу «что не закоммичено — не сделано» рефакторинга `TGSheet`
> **не существует**: ни в дереве, ни в истории. **Это не починка,
> а потерянная работа**, и автора назвать нечем.

### И отсюда правило, которого у нас не было

`projects-c7` положил себе в срез различитель `git log -S 'title: Надпись'` —
и тот был **мёртв уже в момент написания**:

> **Различитель на `git log` бесполезен против незакоммиченного.**
> `-S` ищет по **истории**, а предмет в историю не попал. Против
> правки в общем дереве работает только чтение **дерева**, и только
> **сейчас**: через минуту её может не быть.

Это обратная сторона нашего же правила «мерить коммит, не дерево».
Правило верно для **своего** замера — и оно же делает слепым к тому,
что ломает замер **снаружи**.

**Различитель, который стоит применить ДО разбора любого красного:**

```
мой файл        TogoUITests/ОбщийДневникВидно.swift   ТЕСТОВЫЙ таргет
TGScaffolds     Togo/DesignSystem/Components/         ПРОДУКТОВЫЙ
```

> **Файл тест-таргета не может сломать компиляцию продукта.** Если
> в ошибке продуктовый файл — это не мой долг, сколько бы громко
> он ни был объявлен. Смотреть **чей файл в ошибке**, а не чьё
> объявление громче.

И общий различитель, уже оплаченный 14.10:
`git log -S '<строка из ошибки>' -- <файл>` — с поправкой, что `-S`
находит **пострадавшего**, а не виновного, когда файлы разные. Здесь
они были одним, и `-S` сработал бы.

## 1. Прогнать сценарий отказа приёма и посмотреть кадры

`testОтказПриёмаНеСтираетсяТапомЧеловека` (`ОбщийДневникВидно.swift`).

```
запуск     -UITesting -ИсходПриёма нетСети   БЕЗ -ЧужаяЗона
ожидаемо   тумблер ОСТАЛСЯ ВЫКЛЮЧЕННЫМ + баннер с причиной

кадры      5-отказ-приёма-до-тапа · 6-отказ-приёма-после-тапа
```

Исход объявлен в самом тесте. **Кадры посмотреть глазами** — кадр
существует, когда он снят **и на него посмотрели**; за сегодня
в партии из двенадцати на шесть не смотрел никто, и выяснилось это
счётом, а не взглядом.

Вторым кадром тем же заходом — **карточка состояния после включения
у владельца**: там теперь «Чей дневник: свой» и «Своё не уехало»
вместо нуля при отсутствии движка. Никто этого не видел глазами.

## 2. Сквозная приёмка маминого пути — НЕ ПО ЧАСТЯМ

Правило менеджера, не пожелание. Мамин путь складывается из **двух
правок сразу**: флаг в `TogoApp.swift` (`projects-09`) и тумблер
(`projects-36`).

> **Поодиночке каждая оставляет дорогу разорванной, и обе выглядят
> законченными у своего автора.**

**Граница, названная до прогона:** путь
`ссылка → отказ → экран → тумблер` **нечем пройти целиком
на симуляторе** — приём `CKShare` требует живого второго iCloud,
приватная база неизмерима без её телефона. Значит сквозной кадр будет
**склейкой четырёх состояний, заведённых аргументами запуска**, и он
**не доказывает, что дорога проходится живым человеком**.

Менеджер принял это заранее. Живую дорогу проверяет Виктория
на TestFlight, её слово: «мой телефон забей сейчас, всё проверим
на TestFlight на новой сборке».

## 3. Кадр ворот показа главного экрана — вход НАЙДЕН, замер за `projects-09`

Состояние «гость + онбординг не пройден» считалось недостижимым
на стенде. **Четвёртый путь открыт** (замер 15.10, мой):

```bash
xcrun simctl spawn <udid> defaults write group.app.togo.diary \
    "sharedDiary.ownerName" "мамаТест"
```

`SharedZoneOwner` хранит имя в App Group (`SharedZone.swift:20-23`),
а не в `.standard` — аргумент запуска туда не дойдёт, но `simctl`
пускает. Контроли: несуществующий ключ и несуществующий домен оба
отказали, значит положительный ответ не артефакт.

Порядок: `shutdown → erase → boot → defaults write → launch`.
Приложение **не запущено** в момент записи, иначе `cfprefsd`
переживёт запись.

**Чего мой замер НЕ доказал:** что приложение этот ключ при запуске
подхватывает и уходит в ветку гостя. Третий шаг за `projects-09`,
исход он объявил:

```
ПОСЛЕ починки (f1ab3e3)   ГЛАВНЫЙ ЭКРАН, вкладка «Семья» в кадре
ДО починки                ОНБОРДИНГ, приветствие
```

**Правка ворот отозвана как ненужная** — он сказал это менеджеру сам.
