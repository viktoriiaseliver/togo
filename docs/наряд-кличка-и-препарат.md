## Почему остальное не положено

Правка меняет **тип поля** `TGSheet.title`, которое читают 43 вызова.
Смена закрывалась по лимитам, прогона у меня не было, и
`swiftc -typecheck` занимает на этой машине больше семи минут при
`load average` выше сотни. **Кладу проверяемое, непроверенное —
сюда.** Непроверенная правка каркаса закрыла бы сборку всем, а
277 как раз разрешена к сборке.

## Седьмое решение спринта ролей: напоминания включатся САМИ

Замер `projects-00` на `HEAD`, с контролями:

```
can( / permissions / FamilyResolver в ReminderScheduler.swift   0 вхождений
   КОНТРОЛЬ: строк в файле 271 — ноль не ложный
scheduleDoses:165-173    смотрит только dog.isOnTreatment и dose.ждётОтметки
TodayScreen:430 .task →  ReminderScheduler.refresh при каждом открытии «Сегодня»
   КОНТРОЛЬ: can( в строках 420-432 → 0 · can( во всём файле → 3
единственное, что молчит сегодня — ReminderScheduler:42 guard isAllowed()
```

**Планировщик напоминаний прав не спрашивает вовсе.** Предмет у мамы
уже есть — схемы и дозы приезжают по обмену; запрета нет; нет только
разрешения на уведомления.

> **Защита, работающая по отсутствию разрешения, а не по правилу,
> снимается тем, кто это разрешение выдаёт — и снимается в момент,
> когда он делает доброе дело.**

Снять затычку `.observer` и выдать маме `.giveDose` раньше, чем
в планировщике появится ось, значит включить ей **три уведомления
на каждую дозу, из них два упрёка**: «Доза 21:30 не отмечена ·
Кто-то один — отметьте» и «Доза 21:30 пропущена · Отметь в Togo» —
при запертой кнопке отметки (`DayPlanActions:399 guard
appState.can(.giveDose)`).

**Это седьмое решение, а не производная**, и противоположный выбор
осмысленный: «наблюдатель получает уведомление, чтобы ЗНАТЬ, что доза
пропущена, и позвонить хозяйке». Тогда ось не «кто может отметить»,
а «кто отвечает за собаку», и текст другой — не «отметь»,
а «доза пропущена».

Мой довод к оси «у кого есть `.giveDose`»: **упрёк человеку, который
не может исполнить требование, — наш дефект, а не его
невнимательность.**

**Порядок работ, предложенный `projects-00` и принятый:** ось
в планировщике → роли → повод уведомлений для гостя (пункт 2 выше).
Его собственный пункт **нельзя чинить первым — он сегодня вреден**:
отсутствующее право на уведомления единственное, что отделяет
«мама не получает напоминаний» от «мама получает требования, которые
не может исполнить». Правка — его (`ReminderScheduler.scheduleDoses`
плюс параметр из трёх мест вызова: `TodayScreen:430`,
`DayPlanActions:224`, `:311`).

**Итог по спринту: решений семь, решены три** (роли — защита, «Это я»
убирается, роль назначается при отправке ссылки).
