# 15 октября 2026 — дневник мамы чинится двумя тапами на уже стоящей сборке

Смена `projects-c7`, разработка. Задание Виктории было «довести русскую
версию до TestFlight и посмотреть, что нужно, чтобы всё работало
у меня и у мамы». TestFlight она с сегодня сняла («только онбординг»),
а вторая половина задания оказалась закрыта **без сборки вообще**.

Кода не тронуто ни строки.

## Что сделали

Выключить и включить «Общий дневник» на телефоне Виктории — и всё
накопленное поедет к маме заново. На сборке 276, которая роздана
с 09.10. Новая сборка для этого не нужна.

Четыре замера, каждый с контролем.

### 1. Схема production полна — выгрузкой, а не по наряду

```
xcrun cktool export-schema --environment production   rc=0, 789 строк, 29 типов
код шлёт (Tools/схема_общего_дневника.py)             185 полей в 12 типах
полей, которых в production НЕТ                       0
```

Поимённо по всем двенадцати: `CareTask 18/21 · Clinic 6/9 ·
Diagnosis 7/10 · Dog 35/38 · DogDocument 9/12 · DoseRecord 12/15 ·
LabResult 18/21 · LogEvent 29/32 · Medication 21/24 ·
Prescription 18/21 · VetVisit 8/11 · WeightEntry 4/7` — везде «всё
заведено». Превышение ровно на 3 поля **у всех двенадцати одинаково**,
то есть это системные поля CloudKit, а не наши: систематическое
расхождение не дефект.

> Оговорка про инструмент: первый `grep -c "^RECORD TYPE"` по выгрузке
> дал **0** при 789 строках — строки с отступом. Ложный ноль поймал
> контроль по размеру файла, а не внимательность.

### 2. Путь восстановления существует и срабатывает от тумблера

```
SharedDiaryScreen.turn(on: false) → sync?.stop()
FamilySync.stop()                 → SyncSeedState.сбросить(владелец:)  флаг снят
SharedDiaryScreen.turn(on: true)  → await sync.start()
FamilySync.start()                → fetchNow() → засеять()
FamilySync.засеять()              → SharedDiarySeed.изменения(context:zone:)
                                     собирает из ЛОКАЛЬНОЙ БАЗЫ, не из очереди
```

Поэтому «потерянное не вернётся» верно про **очередь** и неверно
про **данные**: выбыли попытки отправки, а не записи.

И прямым чтением коммита, а не рабочего дерева:

Контроль здесь не формальность: он доказывает, что `git show` читает
коммит, а не мой рабочий файл. **Текст в рабочем дереве выглядит как
текст в git, и различает только `git show`.**

### 4. Отправка карточки собаки больше не отбивается

Дефект начался `a59daeb` 07.10: правка добавила в отправку девять полей
`Dog`, которых в production не было, и **каждая** отправка карточки
отбивалась целиком. Теперь все 35 полей `Dog`, которые шлёт код,
в production есть.

> **Причина снята на сервере, а не в клиенте** — поэтому новая сборка
> для этого не нужна, и это ровно та развилка, которую мы неделю
> не замечали: искали, что собрать, когда чинить надо было то,
> что уже стоит.

## Почему именно так

Задание звучало «довести до TestFlight», и всю неделю из него выводилось
«нужна сборка 277». Но блокер «у мамы не доезжает половина дневника»
жил **не в коде сборки**, а в схеме контейнера. Схему задеплоила
Виктория 14.10. С этого момента предмет задания изменился, а задание —
нет.

> **Утверждение «нужна сборка» состарилось в момент чужого успеха,
> и никто не перечитал его, потому что плохих новостей в тот момент
> не ждали.** Наш класс «условие меняет знак в момент успеха» —
> и впервые в сторону «работы меньше, чем думали».

## Чему тут нельзя верить

1. **Результат не измерен и не мог быть.** Приватная и общая база
   CloudKit неизмеримы без её личного iCloud — второго конца у связи
   нет ни у ключа ASC, ни у токена GitHub. Это вывод из схемы и кода,
   **не замер доставки**. Проверяется только двумя телефонами.
2. **Какая сборка у мамы — неизвестно.** В ASC `Haiane Seliverstova ·
   gayana0505@icloud.com`, группа «Друзья», `INVITED`, тип `EMAIL`;
   рядом безымянный `Anonymous · INSTALLED · PUBLIC_LINK`. Если у неё
   273 — будет «Дневник не открылся» (форма 5.0.0 не открывается),
   и нужна не кнопка, а обновление. `INVITED` отвечает про один вход
   из двух.
3. **Удаления не ездят.** `.deleteRecord` — три вхождения во всём
   дереве, **все три в комментариях**, исполняемых ноль. Поедет текущее
   состояние, а не история правок: удалённое у Виктории у мамы
   останется.
4. **Это про общий дневник, не про зеркало.** `CD_*` неполно: пяти типов
   нет вовсе (`CD_Clinic`, `CD_Diagnosis`, `CD_LabResult`,
   `CD_Prescription`, `CD_VetVisit`). Зеркало — копия своего дневника
   в своём iCloud, то есть второе устройство **того же** человека.
   Кнопок две, и эта вторая.
5. **Пригласить маму заново по-прежнему трудно:** дверь «Семья»
   обрезана (`FamilyScreen:200-206`, кадр `0ee811b`), онбординг
   кончается на третьем шаге из шести. Но если она уже принята в зону,
   данные поедут.

## ПОПРАВКА: «двух тапов» НЕ ХВАТАЕТ, и инструкция без третьего шага молчит

Дыру в моей же инструкции нашла `projects-c5`, её замер; проверил своим
чтением и подтверждаю, плюс нашёл вторую половину механизма.

**`sync?.stop()` — опциональная цепь, а сброс флага живёт только внутри
`stop()`.**

```
SharedDiaryScreen:214     turn(on: false) → sync?.stop()
FamilySync.stop():210     SyncSeedState.сбросить(…)   ЕДИНСТВЕННОЕ вхождение
                                                      во всём дереве — проверено
FamilySync.засеять():179  guard !SyncSeedState.засеяно(…) else { return }
```

При `sync == nil` выключение не делает **ничего**: флаг остаётся
«засеяно», включение поднимает движок, и тот молча выходит из засева
на первой же строке. Экран при этом говорит «включён».

**И оба показания экрана врут согласованно, в сторону «всё хорошо»:**

```
SharedDiaryScreen:116-118  switch sync?.state { case .none, .off: «выключен» }
                           → nil и настоящее «выключено» дают ОДНО слово
SharedDiaryScreen:95       «Своё не уехало»: "\(sync?.pending ?? 0)"
                           → при nil НОЛЬ, то есть «всё отправлено»
```

> Это третий случай того же класса на одном экране. Первые два уже
> записаны: «Своё не уехало» считало длину очереди вместо потерь,
> а `pending` при `nil` даёт ноль. **Величина и подпись отвечают
> на разные вопросы, и расходятся там, где цена максимальна.**

**Вторая половина, которую нашёл я: перезапуск — не предосторожность,
а единственное, что создаёт движок.**

```
TogoApp:316  .task { await startSyncIfOn() }        на запуске
TogoApp:234  guard SharedDiarySettings.isOn, let container else { return }
TogoApp:244  if sync == nil { sync = FamilySync(…) }
TogoApp:248  await sync?.start()
```
Точка создания **одна** (`FamilySync(` — одно вхождение во всём дереве,
`TogoApp:245`), и она под условием «обмен включён». Значит после полного
перезапуска при включённом обмене `sync` существует наверняка,
а без перезапуска — только если его подняли в этом же сеансе.

`выключитьОбмен()` на запуске (`TogoApp:170`) живого человека
не касается: `guard isUITesting else { return }`.

## Что дальше и зачем

Менеджеру отдано **порядком из трёх шагов, а не кнопкой** — первый шаг
не наш, а третий существует только потому, что второй может промолчать:

```
1  спросить МАМУ номер её сборки (Настройки → Togo, либо TestFlight)
   единственный способ: ASC этого не отдаёт никаким запросом
2  ПОЛНЫЙ ПЕРЕЗАПУСК приложения у Виктории, затем открыть «Общий
   дневник» и ПРОЧИТАТЬ строку «Обмен». Если там «выключен» — дальше
   не идти: это слово означает и «выключено», и «движка нет»
3  если строка живая и сборка у мамы 275 или 276 — выключить
   и включить «Общий дневник» и посмотреть, появились ли у неё
   карточка собаки и медкнижка
```

Шаг 2 ничего не стоит и единственный отличает рабочий случай
от молчащего.

Цена ошибки в одну сторону ноль: тумблер обратим, засев собирается
из локальной базы, данные не теряются. В другую — мы ждём 277 ради
того, что уже работает.

**И граница формулировки, которую я прошу удержать при пересказе.** Это
не «починено»: это «есть основание проверить за две минуты, и вот
почему». Разница в том, что первое закрывает вопрос, а второе его
задаёт — а доставку не мерил никто.
