### Правка этой записи моей рукой: два числа были мои и были неверны

Первая редакция говорила «имён вердикта ✔ 3» и объясняла третий

Строка итога **начинается с `✔ Test `** — и мой счётчик имён считал её

> **Счётчик, который должен был заменить строку итога, посчитал её как
> одно из имён.** Шаблон опирался на начало строки, а различать надо
> было кавычку после `Test`: у вердикта она есть, у итога нет.

### Правка четвёртая, и она снимает моё же предложение целиком

Сперва здесь стояло: «воротами становится сверка плюс имена, а `rc`,
`Restarting` и `caught` ворот не держат; критерий „ноль перезапусков“
в `Tools/эталон-прогона.json` измеримо неверен».

**Неверны оба утверждения.** Прочитал, КАК сверка считает
(`Tools/сверить_эталон.py:160-188`), а не что она печатает:

```python
if "Mach error -308" / "server died"               → «это стенд»
if "Early unexpected exit"                         → «это стенд»
if "uncaught exception" / "Terminating app due to" → «это стенд»
if not счёты                                       → «не дошёл до конца»
перезапуски = текст.count("Restarting after unexpected exit")
if перезапуски                                      → «перезапусков N — это стенд»
выполнено = min(счёты); if выполнено < порог        → «замер не состоялся»
```

Критерий живёт **в коде сверки, а не в json**, и «ноль перезапусков»
там уже есть — **как отказ**. Моё предложение «Restarting ворот
не держит» было бы **ослаблением здорового инструмента**: для ворот
перезапуск — верный отказ, потому что прогон с перезапуском не измерил
того, что обещал.

Что в сверке действительно слабое — и слабое в сторону тревоги:
`выполнено = min(счёты)` берётся из **строки итога**, то есть из числа,
которое мы в тот же день измерили как **занижающее** (9 против 16
по именам), и берётся **наименьшее** из напечатанных, нарочно.

> **«Выполнено» у сверки занижено дважды — строкой итога и выбором
> минимума.** Для ворот это верно: инструмент, ошибающийся в сторону
> тревоги, не пропускает плохое. Для измерения прогресса негодно:
> «выполнено 9» не значит, что прошло девять.

Отсюда разделение: **ворота — сверка как есть, не трогать**; «сколько
прошло» — отдельное число по именам, печатать рядом и в ворота
не подставлять. Имена сверка извлекает уже верно, без якоря и с
кавычкой, — то, что я рекомендовал, в ней стоит, и «починка» туда была
бы правкой здорового.

## Строка чистоты, растущая от артефактов самого замера

Мой скрипт печатал «грязных 2», потом «грязных 6» — на одном и том же
дереве, где исходного не менялось ничего. Число росло моей же
оснасткой: скрипты, логи, `.xcresult`, `DerivedData`.

```
git status --porcelain | grep -vE '^\?\?' | wc -l    →  0 отслеживаемых изменённых
всего строк git status                               → 13, ВСЕ мои артефакты
```

> **Строка чистоты, чьё число растёт от артефактов самого замера,

останется; а шесть повторов на `serial` — долг без хозяина, и назвать
его надо долгом, а не отсутствием.

Это пятый случай за смену одного класса — и первый, где я не проверил
не шаблон и не вывод, а **происхождение числа**. Рядом с «у дифа нет
автора, у коммита есть»: у числа в письме автора тоже нет, и по виду
оно моё.

## Чем каждое утверждение выше проверяется за минуту

Записи без способа проверки становятся преданием, а логи моих прогонов
лежат в `/tmp` — то есть улика на этой машине есть улика нигде. Поэтому
проверяемое не моими логами, а деревом и инструментами:

```bash
# «make build съедает код возврата» — форма воспроизводится игрушкой
printf 'A:\n\t@false \\\n\t\t| tail -5\n' > /tmp/d.mk && make -f /tmp/d.mk A; echo $?
#   даёт 0 на упавшей команде. Строка Makefile:51-52 — той же формы

# «ворота архива держат» — на том, что лежит на диске, без подделки
bash Tools/archive_fingerprint.sh build/Togo.xcarchive; echo "rc=$?"
#   rc=3, «НОМЕР АРХИВА НЕ ТОТ»

# «раздача берёт последнюю, а не ту»
grep -n 'limit=1&sort=-uploadedDate' Tools/publish_beta.sh Tools/submit_beta_review.sh
grep -c 'номер-сборки' Tools/publish_beta.sh Tools/submit_beta_review.sh   # 0 и 0

# «заметки говорят про 274»
head -1 fastlane/metadata/ru/testflight_whats_new.txt

# «языки в ОБОИХ бандлах» — последнее звено, не каталог
bash Tools/check_bundle_languages.sh <путь к .app или .xcarchive>

# «у графика блокер в данных, а не исполнитель»
sed -n '194,209p' Togo/Features/Health/LabChartScreen.swift
grep -n 'LabChartScreen' Togo/Features/Health/HealthScreen.swift   # дорога есть

# «RecallParser/Writer не зовутся вне тестов»
grep -rn 'RecallParser\|RecallWriter' --include='*.swift' . | grep -v Tests

# «свёртка меток мочи живёт и вызывается»
grep -rn 'markGroups' --include='*.swift' Togo TogoShared

# «ci_simulator сделан нарочно иначе» — довод в самом файле
sed -n '69,72p' Tools/ci_simulator.py

# «ArchiveFieldValueTests и так был последовательным» — опровержение
# кандидата, лежащее в исходнике и не зависящее от флага
grep -n '@Suite' TogoTests/ArchiveFieldValueTests.swift   # .serialized

# «хранилище на диске создаёт сам тест, erase его не лечит»
grep -n 'togo-migration' TogoTests/SchemaMigrationTests.swift
```

Чего этим списком проверить **нельзя** и о чём надо говорить прямо:
числа самих прогонов (`rc=65`, перезапуски, счёт исключений) живут
в логах `/tmp/togo-a5-2938/` и **уйдут вместе с машиной**. Они
воспроизводятся только повтором прогона, и повтор может дать другие
числа — флак стоит двух запусков и переживает изоляцию. Поэтому
в записи важны не величины, а то, **что они опровергают**: признак,
опровергнутый один раз, опровергнут.
