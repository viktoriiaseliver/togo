## Третий красный, который есть только в рабочем дереве

Ворота заливщика не пропустили первую попытку: «Упало тестов: 3».
Третьим был `СнятиеНапоминанийПодключеноTests.правилоОдно` —
`Code=260`, «не удалось открыть файл «ПозваливСемью.swift»».
Настоящее имя — `ПозвалиВСемью.swift`, с заглавной «В».

```
основное дерево, e9af370f    КРАСНЫЙ, воспроизводится стабильно
worktree,        e9af370f    ЗЕЛЁНЫЙ, 3 теста из 3
вчерашний прогон 29.10       Code=260 → 0, тест проходил
find по обоим деревьям       списки .swift побайтово идентичны, 252 = 252
os.path.exists обоих имён    True и True (ФС регистронезависима)
```

**Механизм найден тем же вечером:** `resolvingSymlinksInPath()` делает
case-folding кириллицы. Замер обходом с печатью байтов:

```
lastPathComponent          … d092 …   «В» заглавная, как на диске
адрес.path                 … d092 …   верно
resolvingSymlinksInPath()  … d0b2 …   «В» стала строчной «в»
```

Том регистронезависим — на хосте испорченное имя открывается (файл
прочитался, 10 442 символа). В симуляторе тот же путь даёт «No such
file». Из worktree под `/tmp` резолв имя не портит, потому прогон
по своду и был зелёным.

Прежняя запись в коде говорила ровно обратное — «из рабочего дерева
сторож работает, из worktree не работает никогда», — и перевернулась
на той же строке. Оба класса дают `Code=260` на первом же файле
обхода и по симптому неразличимы.

Затронуто пять сторожей, кириллических имён в продукте 28 — ловушка
на каждый двадцатый файл. Два сторожа из пяти не падали вовсе:
портился только адрес в их отчёте, по которому человек шёл искать
несуществующий файл.

**И первая редакция починки ввела свой отказ, зеркальный прежнему.**
Она считала глубину по нерезолвленному основанию: в рабочем дереве
совпадало, в worktree давало `Togo/Togo/Store/…`. Полный прогон
показал 11 issues вместо двух — девять сторожей смотрели в пустоту.

```
рабочее дерево   счёт от основания → Togo/Store/SeedData.swift   верно
worktree /tmp    счёт от основания → Togo/Togo/Store/SeedData.swift
                 хвост по резолву  → Togo/Store/SeedData.swift   верно
```

Итог: длина хвоста — по резолвленным путям, имена — из нерезолвленного
адреса. Сторож на класс — `ИменаФайловПриОбходеTests`, принят
подделкой: покраснел и назвал ровно тот файл, который сломали.

> Своё участие назвать прямо: путь к этому файлу я печатала руками
> со строчной «в» — и в вызове Edit, и в доккомментарии. К падению это
> отношения не имело, виноват был резолв. **Правдоподобное совпадение
> чуть не стало объяснением** — различил замер, а не сходство.

## Почему именно так

Решение 07.10 скрывать безымянные записи стояло на доводе: «от фантома
такая запись неотличима ничем — ни кличкой, ни связями». Довод был
верен ровно до тех пор, пока безымянные ничего не тянули.

Журнал маминого телефона 30.10 09:37:

```
07A377E6   ev 214  w 25  care 19  med 10     — 268 связей
71FBB678   ev 44   doc 15                    —  59 связей
42377768   ev 13   care 1                    —  14 связей
```

Её кадр в ту же минуту (`.отзывы/Togo/2026-10-30_0947-AB9HB73b-1.jpg`):
«Дневник едет на этот телефон», «Пока пусто», четыре нуля. Плашка
рисуется при `dog == nil` (`TodayScreen:236`), а `activeDog` берёт
из `shownToPerson`. **Кадр доказывает нулевой показ при 341 связи
в базе** — связи и есть тот различитель, которого 07.10 не нашли.

**И самоисправление, обещанное тем же решением, не наступило бы.**
Контроль нашёлся в соседнем поле того же вида — у одной и той же
записи `C1469CE8` на двух телефонах:

```
у владельца   created 2023-03-19T12:00:00Z   ev 28 w 24 care 8 med 9 doc 15
у гостя       created 2026-10-28T13:48:37Z   связей 0
```

`createdAt` объявлен `= Date()` (`Dog.swift:166`), `name` — `= ""`
(строка 30). Второе значение — не данные, а **дефолт, сработавший при
материализации объекта**. Двадцать одно поле из двадцати двух доехало;
не доехали ровно те два, у которых есть дефолт, и на одном из них
стоял весь показ. «Появится сама, когда доедет кличка» верно для
недогруженной записи и ложно для недоставленного атрибута.

## Что это меняет для человека с собакой

Мама третий день держала в руках пустое приложение поверх полного
дневника. Три её жалобы в одном отзыве 30.10 09:47 читаются как три,
а это одна: «не работает кнопка» — кнопок записи нет без собаки;
«не видно что было сегодня» — ноль видимых; «сложно подключиться» —
плашка обещает минуту третий день.

Хронология того утра, два журнала рядом:

```
09:33:29  Виктория   familyMember + invite
09:34:21  мама       acceptByLink:failed
09:37:08  Виктория   invite (второй)
09:38:22  Виктория   invite (третий)
09:41:47  Виктория   familyMember + invite (четвёртый)
```

После первого отказа мама **не сделала ни одной повторной попытки** —
десять минут ходила по экранам (настройки 41 раз) и ушла в `usageLog`.
Приглашения летели в телефон, который уже считал себя подключённым:
`SharedZoneOwner.isGuest` истинно, имя владельца известно.

## Что дальше и зачем

- **Наложение и обрезка фона — девять отзывов из двадцати двух,
  и в 287 этого нет.** Дефект виден на кадрах (вертикальный шов
  на ~82 % ширины у «Истории», статус-бар поверх заголовка у мамы),
  но не воспроизведён. Чинить по кадрам вслепую — гадать; нужен
  заход со стендом и своими кадрами.
- Жалобы на фон приходят ровно в минуты перебора `background.mode`:
  27.10 19:31 `single → auto` → отзыв 19:32; 29.10 14:52 четыре
  переключения → отзыв 14:52; 29.10 21:48 семь подряд. Это вход,
  с которого начинать воспроизведение.
- Откуда берутся фантомы: девять записей за три дня, и каждая создана
  **в секунду переписи какого-то запуска** (`AB8E96E0` 19:18:30 —
  секунда открытия онбординга, остальные восемь — обычные запуски).
  `NamelessDogAudit` держит этот вопрос открытым с 07.10 как
  «не установлено»; теперь у него девять случаев и правдоподобный
  механизм — `createdAt` печатает момент материализации, а не рождения.

## Открытые вопросы

- **Почему к маме не едут записи, хотя она гость.** `isGuest` истинно,
  имя владельца известно, часть собак приехала — а «Забрать сейчас»
  не наполняет день. Измерить нечем: приватная база CloudKit
  неизмерима без её личного iCloud, второго конца у связи нет.
- **Улика `namelessDog` не различает «нет клички» и «удалена»** —
  у `canBeShown` два слагаемых, а в строку не печатается ни одно.
  Для `07A377E6` (268 связей) это значит, что мы не знаем, её это
  дневник или надгробие. Дефект самой улики, не починен.
- **«Нужно хотя бы 3 дня с записями — пока их 2»** на кадре 30.10,
  а в журнале выходы отмечены в три разных дня (27, 28, 29; смещение
  +1 ни одной записи через полночь не переносит). Не разобрано.
- **Два `finish:walk` подряд 30.10 08:06 и ни одной `record:walk`
  в журнале** — при том что прогулка в ленте есть («08:50 → 09:06,
  15 минут»). Пропала строка журнала, не выгул; путь не найден.
- Моё «прогулка потеряна» было **опровергнуто кадром того же утра**,
  и опровергло его не рассуждение, а снимок, приложенный человеком.
  Журнал отвечает про себя: «я не отметил» и «этого не было» —
  у него одна форма.
