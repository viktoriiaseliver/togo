## Почему именно так

### Пункт наряда «поставить `@Attribute(.unique)`» — не работа, а невозможность

Первым шагом полагается проверить, что пункты ещё нужны. Этот
не нужен и не может стать нужным:

```
@Attribute(.unique) в продуктовом коде          0 вхождений
единственное упоминание  доккомментарий теста SharedDogTests:255
Persistence.swift:211-214  cloudKitDatabase: .private(…)
```

Хранилище зеркалится в CloudKit, а зеркало уникальных ограничений
не допускает. Значит от дубликата защищает **ровно одно** — выборка
по `id` в коде приёма. Проект это знал и записал тестом, а не
комментарием (`SharedDogTests:253-290`): «хранилище не склеивает двух
собак с одним `id` — это делает наш код».

### Эта защита обёрнута в `try?` во всех двадцати семи местах

```
выборок вида #Predicate { $0.id == id } в TogoShared/Sync   27
из них под try?                                             27
форм с разбором ошибки                                       0
```

Два способа сошлись: `git grep -c` по файлам даёт 12 + 15; счёт строк
с `try?` в контексте `-B1` даёт 27.

```swift
let existing = try? context.fetch(
    FetchDescriptor<Dog>(predicate: #Predicate { $0.id == id })
).first

guard let local = existing else {
    let dog = Dog(name: payload.name, weightKg: payload.weightKg)
    dog.id = payload.id          // ← тот же id, НОВАЯ строка
    context.insert(dog)
```

`try?` превращает отказ выборки в `nil`, то есть в «такой собаки нет».
Ответ кода на «нет» — завести новую.

> **Несостоявшийся замер здесь не молчит — он создаёт дубликат.
> Отказ падает не в безопасную сторону, а ровно в ту, от которой
> стоит защита.**

Что делает находку адресной, а не придиркой к стилю, — **асимметрия**:
у записи проект этот класс закрыл нарочно (`Persist.swift:48`,
`persist(otherwise:)`, и она же вызвана строкой ниже, в `:691`),
а у чтения соглашения нет вовсе. И цена промаха у чтения выше:
несохранённая запись теряется, несостоявшаяся выборка — размножается.

Проект уже снимал ровно этот `try?` однажды.
`SharedDiaryFetchFailureTests` заведён 24.09 после двух суток пустого
экрана у второго человека: «в `fetchNow` стояло `try?`, ошибка уходила
в никуда». **Класс закрыт в одном вызове из двадцати восьми.**

## Ложный ноль, на котором я чуть не доложил неверное

Проверяя, попал ли мой сторож в чужую сборку, я померил дважды и
получил разное про **один и тот же файл**: `grep` сказал «нет»,
разбор множеством имён — «есть». Развёл:

```
СвойствоМимоКаталогаTests.swift   count(NFC)=0   count(NFD)=5
ОтказВыборкиПоIdTests.swift       count(NFC)=0   count(NFD)=0
формы хранения в логе             NFC 20 имён · NFD 4 имени
мой файл на диске                 NFC
```

**Логи сборки хранят кириллические имена файлов в двух нормализациях
Unicode разом.** Поиск по литералу, набранному в одной форме, даёт
ложный ноль на файлах, записанных в другой, — и выглядит он как «файла
в сборке нет».

> Поиск по кириллическому имени файла отвечает про алфавит, а не
> про сборку, пока обе стороны не нормализованы.

И первая моя проба была хуже ложного нуля: форму хранения я определил
**по первому попавшемуся имени** — выборкой из одного, и она сказала
«NFC» про лог, где четверть имён NFD.

Ответ на исходный вопрос при этом твёрдый и дан **обеими формами**:
моего файла в том прогоне нет ни в одной. Файл лёг на диск в 14:21:35,
а лог начат в 14:12:56 — сборка прочитала состав `TogoTests` раньше,
чем файл появился. Это **«ответить нечем»**, а не «собралось».
