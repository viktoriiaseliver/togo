## Главная находка: один `guard` стоит на два вопроса

`TogoUITests/ОнбордингНиз.swift`, `замерить(_:кнопка:)`, на `d180d27`:

```swift
guard !app.keyboards.element.exists else {
    print("ЗАМЕР \(имя) — НЕГОДЕН: КЛАВИАТУРА ПОДНЯТА … Число не печатаю НАРОЧНО")
    снять("\(имя)-НЕГОДЕН-клавиатура-поднята")
    return nil
}
```

Шаг «Кто у тебя живёт» режет содержимое **только при поднятой
клавиатуре**. Сторож, доходя до этого состояния, числа не печатает
и возвращает `nil`.

```
замер экрана, клавиатура опущена   перекрытие ≤ 0, зелено
замер того же, клавиатура поднята  НЕГОДЕН, числа нет вовсе
дефект человека                    живёт во второй строке
```

Отбраковка **верна** для вопроса, под который написана: после
`c3fc0a8` тап в заголовок стабилизировал раскладку, и `165 pt` стало
печататься «как годное», будучи высотой клавиатуры, а не дефектом
вёрстки. Для вопроса «встала ли вёрстка» это мусор.

Но для вопроса «видит ли человек „Дату рождения“, пока набирает
вес» `165 pt` — не мусор, а **предмет**: текст в этот момент
действительно под панелью, и человек смотрит именно на это.

> **Один `guard` стоит на два вопроса и отвечает «не знаю» на тот,
> который никто не задавал вслух.** Отбраковка верна и слепа
> одновременно, и слепота наследует доверие к правоте.

### Это объясняет запись, которая дважды была основанием

`CLAUDE.md`: «кадров с поднятой клавиатурой ТРИ, и все три НЕГОДНЫЕ».
Их снимает **сам этот `guard`** строкой
`снять("…-НЕГОДЕН-клавиатура-поднята")`. Не три неудачи оператора —
**три штатных отказа одного механизма**.

Формулировка «условие стенда есть, а годного замера в нём нет
ни одного» верна, и теперь названа причина: годного замера в этом
условии стенд не умеет снимать **вовсе**.

> **Дефект прожил не потому, что его не искали, а потому, что
> у него не было измерителя — и отсутствие измерителя выглядело
> как три негодных кадра.**

Это четвёртая корзина в новом виде: не «погас прокси» (сторож зелен,
предмет жив), а **«сторож отказался отвечать, и отказ выглядел
как результат»**. Лечится не эталоном и не осью, а **вторым путём
рядом с первым**: `guard` остаётся для «встала ли вёрстка», новый
замер — для «накрыт ли текст при клавиатуре», и различать их обязаны
имена замера и кадра.

Решение `projects-c5` (автор сторожа): форму принял, **кладёт после
своей приёмки, не во время** — «новый сторож, заведённый внутри чужой
приёмки, красит её своим предметом; если второй путь окажется
красным, красным станет прогон, которым принимают починку обрыва,
и разбирать будут не то». Довод сильнее срока.

## Правка: низ `DogStep` отдан системе

`Togo/Features/Onboarding/OnboardingSteps.swift`. Слот `} bottom: {`
→ `.safeAreaInset(edge: .bottom)`, **один экран из сорока**.

Механизм (установлен менеджером, не перемерен): слот каркаса считает
запас от высоты **самой панели** (`TGScaffolds.swift:177`,
`запасПодНизом = высотаНиза + s24`), а панель в нём — сосед
по `ZStack`, не inset. Клавиатура панель поднимает и высоту её
не меняет: запас остаётся прежним, содержимое уходит под панель.
Замер с кадра — `minY` панели 446 против 772, Δ **326 pt**
недостижимо даже полной прокруткой.

Почему один экран: `safeAreaInset` рядом с полем ввода в этом проекте
**не измерен ни разу** — все четыре живых места (`TodayScreen:149`,
`VetSummaryScreen:283`, `SitterBriefingScreen:58`,
`OnboardingFlow:119`) это экраны **без полей ввода**. «Документировано
Apple» здесь не равно «измерено».

**Сторож `ЗапасПодНизомTests` не тронут, и это замер, а не слово:**
`git diff --stat` по `TGScaffolds.swift` пуст, ось сторожа
(`высотаНиза` · `GeometryReader` · `Color.clear`) на месте целиком.
Сторожа на счёт слотов `} bottom: {` в тестах нет — эту мысль
`ЗапасПодНизомTests:28-40` рассмотрел и отверг нарочно, как «верную
по счёту случайно».

**Побочное, названное скиллом `/ios-inzhener`, а не мной:** у `TGScreen`
слой замера создаётся только при непустом слоте
(`if Bottom.self != EmptyView.self`). Значит `DogStep` после правки
не инстанцирует ни `GeometryReader`, ни `@State высотаНиза` —
звено «вёрстка → `@State` → перерисовка» с этого экрана уходит.
Производительность **не мерена**, утверждается только состав дерева.

Выход с цифровой клавиатуры. У `.decimalPad` нет клавиши возврата,

зелёное одного прочтётся как готовность обоих.

## Развилка механизма клавиатурного выхода — цена обоих

Решение менеджера, не моё. Числа **не сошлись близко**: 27 правок
против 7.

```
11 полей .decimalPad · 5 файлов · 7 ЭКРАНОВ-владельцев
  DogStep · HealthScreen:510 · PrescriptionScreens:253
  Editors:33 · Editors:533            — по одному полю
  LabResultEntryFlow:211              — ТРИ поля, нужен enum
  LabResultRowEditor:535              — ТРИ поля, нужен enum

А  resignFirstResponder   7 применений, 0 объявлений, 0 enum
Б  @FocusState            7 объявлений + 11 .focused() + 2 enum
                          + 7 применений = ~27 правок
```

**Выбор обратим за один файл, и это снимает спор.** Механизм показа
панели в обоих вариантах один и тот же — `ToolbarItemGroup(placement:
.keyboard)` + `Spacer` + `Button("Готово")`. Различается только то,
что делает кнопка:

```swift
А   Button("Готово") { UIApplication.shared.sendAction(
        #selector(UIResponder.resignFirstResponder), to: nil, from: nil, for: nil) }
Б   Button("Готово", action: снять)      // экран передаёт своё снятие
```

Ни один из семи адресов применения при смене варианта не меняется.
То есть это не «вторая константа рядом с первой», где обе остаются
жить, — здесь заменяется одна строка в одном месте.

> Развилка выглядела решением о механизме, а является решением
> **о порядке работ**.

**И довод за Б, который надо снять — он ложный.** Б защищают тем,
что связь видна компилятору. Проверено: удали поле — `case`
перечисления останется, `@FocusState` останется, **компилятор
промолчит**. Б краснеет на опечатке в имени `case`, а не
на исчезновении поля.

Что есть у Б по-настоящему: UIKit не нужен, снимается фокус только
у своего поля. Что есть у А: **новое поле `.decimalPad` получает выход
в тот же день, когда появляется**, без того, чтобы кто-то про него
вспомнил; у Б новое поле молча останется без выхода — тот самый класс
«механизм есть, вход не заведён».

`UIApplication` чужеродным в проекте не является: он уже стоит
в восьми файлах, и в **этом же каталоге** —
`Togo/DesignSystem/ЯркостьЭкрана.swift:51`. Изоляция проекта —
`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`
(`Tools/generate_project.py:405`), оба варианта по изоляции верны.

Оба текста лежат целиком **здесь** (ниже), а не только
в `/tmp/togo-69-отложено/`: у отвергнутого кандидата должен остаться
адрес в git, иначе следующий напишет его третий раз. Замечание
`projects-8d`, и оно верное.

### Вариант А целиком

```swift
extension View {
    func готовоНадКлавиатурой() -> some View { modifier(ГотовоНадКлавиатурой()) }
}

private struct ГотовоНадКлавиатурой: ViewModifier {
    func body(content: Content) -> some View {
        content.toolbar {
            ToolbarItemGroup(placement: .keyboard) {
                Spacer()                      // без него «Готово» встанет слева
                Button("Готово") { Фокус.снять() }
            }
        }
    }
}

@MainActor
private enum Фокус {
    static func снять() {
        UIApplication.shared.sendAction(
            #selector(UIResponder.resignFirstResponder), to: nil, from: nil, for: nil)
    }
}
```

### Вариант Б целиком

```swift
extension View {
    func готовоНадКлавиатурой(снять: @escaping () -> Void) -> some View {
        toolbar {
            ToolbarItemGroup(placement: .keyboard) {
```
