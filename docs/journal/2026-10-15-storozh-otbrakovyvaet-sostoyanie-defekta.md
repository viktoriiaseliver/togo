## Главная находка: один `guard` стоит на два вопроса

`TogoUITests/ОнбордингНиз.swift`, `замерить(_:кнопка:)`, на `d180d27`:

```swift
guard !app.keyboards.element.exists else {
    print("ЗАМЕР \(имя) — НЕГОДЕН: КЛАВИАТУРА ПОДНЯТА … Число не печатаю НАРОЧНО")
    снять("\(имя)-НЕГОДЕН-клавиатура-поднята")
    return nil
}
```

Шаг «Кто у тебя живёт» режет содержимое **только при поднятой
клавиатуре**. Сторож, доходя до этого состояния, числа не печатает
и возвращает `nil`.

```
замер экрана, клавиатура опущена   перекрытие ≤ 0, зелено
замер того же, клавиатура поднята  НЕГОДЕН, числа нет вовсе
дефект человека                    живёт во второй строке
```

Отбраковка **верна** для вопроса, под который написана: после
`c3fc0a8` тап в заголовок стабилизировал раскладку, и `165 pt` стало
печататься «как годное», будучи высотой клавиатуры, а не дефектом
вёрстки. Для вопроса «встала ли вёрстка» это мусор.

Но для вопроса «видит ли человек „Дату рождения“, пока набирает
вес» `165 pt` — не мусор, а **предмет**: текст в этот момент
действительно под панелью, и человек смотрит именно на это.

> **Один `guard` стоит на два вопроса и отвечает «не знаю» на тот,
> который никто не задавал вслух.** Отбраковка верна и слепа
> одновременно, и слепота наследует доверие к правоте.

### Это объясняет запись, которая дважды была основанием

`CLAUDE.md`: «кадров с поднятой клавиатурой ТРИ, и все три НЕГОДНЫЕ».
Их снимает **сам этот `guard`** строкой
`снять("…-НЕГОДЕН-клавиатура-поднята")`. Не три неудачи оператора —
**три штатных отказа одного механизма**.

Формулировка «условие стенда есть, а годного замера в нём нет
ни одного» верна, и теперь названа причина: годного замера в этом
условии стенд не умеет снимать **вовсе**.

> **Дефект прожил не потому, что его не искали, а потому, что
> у него не было измерителя — и отсутствие измерителя выглядело
> как три негодных кадра.**

Это четвёртая корзина в новом виде: не «погас прокси» (сторож зелен,
предмет жив), а **«сторож отказался отвечать, и отказ выглядел
как результат»**. Лечится не эталоном и не осью, а **вторым путём
рядом с первым**: `guard` остаётся для «встала ли вёрстка», новый
замер — для «накрыт ли текст при клавиатуре», и различать их обязаны
имена замера и кадра.

Решение `projects-c5` (автор сторожа): форму принял, **кладёт после
своей приёмки, не во время** — «новый сторож, заведённый внутри чужой
приёмки, красит её своим предметом; если второй путь окажется
красным, красным станет прогон, которым принимают починку обрыва,
и разбирать будут не то». Довод сильнее срока.

## Правка: низ `DogStep` отдан системе

```
                          + 7 применений = ~27 правок
```

**Выбор обратим за один файл, и это снимает спор.** Механизм показа
панели в обоих вариантах один и тот же — `ToolbarItemGroup(placement:
.keyboard)` + `Spacer` + `Button("Готово")`. Различается только то,
что делает кнопка:

```swift
А   Button("Готово") { UIApplication.shared.sendAction(
        #selector(UIResponder.resignFirstResponder), to: nil, from: nil, for: nil) }
Б   Button("Готово", action: снять)      // экран передаёт своё снятие
```

Ни один из семи адресов применения при смене варианта не меняется.
То есть это не «вторая константа рядом с первой», где обе остаются
жить, — здесь заменяется одна строка в одном месте.

> Развилка выглядела решением о механизме, а является решением
> **о порядке работ**.

**И довод за Б, который надо снять — он ложный.** Б защищают тем,
что связь видна компилятору. Проверено: удали поле — `case`
перечисления останется, `@FocusState` останется, **компилятор
промолчит**. Б краснеет на опечатке в имени `case`, а не
на исчезновении поля.

Что есть у Б по-настоящему: UIKit не нужен, снимается фокус только
у своего поля. Что есть у А: **новое поле `.decimalPad` получает выход
в тот же день, когда появляется**, без того, чтобы кто-то про него
вспомнил; у Б новое поле молча останется без выхода — тот самый класс
«механизм есть, вход не заведён».

`UIApplication` чужеродным в проекте не является: он уже стоит
в восьми файлах, и в **этом же каталоге** —
`Togo/DesignSystem/ЯркостьЭкрана.swift:51`. Изоляция проекта —
`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`
(`Tools/generate_project.py:405`), оба варианта по изоляции верны.

Оба текста лежат целиком **здесь** (ниже), а не только
в `/tmp/togo-69-отложено/`: у отвергнутого кандидата должен остаться

## Три ложных успеха за один час, и все три на знающем правило

### 1. Уведомление фоновой задачи сказало «exit code 0» при `rc=1`

```
уведомление   completed (exit code 0)
файл с кодом  rc=1
лог замера    НЕ СУЩЕСТВУЕТ ВОВСЕ
файлы в worktree  НЕТ: grep модификатора 0
```

`git checkout d7e275b` **отказал** — в моём worktree лежала моя же копия
`OnboardingSteps.swift` от прошлого замера («Your local changes would
be overwritten»). Цепочка оборвалась **до** `swiftc`, лог не создался,
а код уведомление взяло от последней команды — `cat`, которая успешно
прочитала файл с единицей внутри.

> **«Код возврата приезжает от последнего звена» написано у нас про
> конвейер. Оно действует и на хвост цепочки `&&`, и на уведомление
> фоновой задачи.** Я поставил `cat` в конец, чтобы увидеть результат,
> — и этим превратил отказ в успех для того, кто смотрит
> на уведомление.

Форма: `rc` писать **сразу после измеряющей команды** и после неё
не ставить ничего. И проверять не только код — **состоялся ли замер
вообще**: есть ли лог, лежат ли на месте измеряемые файлы.

### 2. Проверка, вписанная в доккомментарий, считала прозу

Менеджер велел положить рядом с модификатором проверку за минуту:
«`grep` полей против `grep` модификатора». Первая редакция искала
слово `decimalPad` без оси и без вырезания комментариев:

```
grep по слову decimalPad              20   ← считает ПРОЗУ
grep по keyboardType(.decimalPad)     12   ← одно в чужом /// тоже
то же, с вырезанным ///               11   ← настоящие поля
```

**Девять лишних вхождений из девятнадцати — мои собственные
доккомментарии про эту же проверку.**

> **Проверка, запрещающая писать о себе, ломается первой же записью
> о себе.** Ось берётся от того, **что вызывается**
> (`keyboardType(.decimalPad)`), а не от того, как предмет называется
> в тексте.

Класс известен — «сторож меряет прозу», и `ЗапасПодНизомTests`
закрывает эту дверь своим `код(_:)`. Я эту защиту прочитал в его файле
за час до и всё равно не применил у себя. **Обе редакции оставлены
в голове модификатора с замером рядом:** удалённая о себе
не предупреждает.

И отдельно — **направление ошибки**: 20 > 11 читается как «выходов
больше, чем полей», то есть сломанная проверка врала **в сторону
„всё хорошо“**.

## Порядок изменён менеджером, и довод стоит записать

Его правило было «сначала один экран, потом замер, потом остальное»,
и я готов был ждать кадра. Он снял своё правило сам:

> Порядок «сначала замер» был про **риск общего каркаса**: там
> неподтверждённая форма разъехалась бы по сорока экранам. Здесь риска
> нет — модификатор положен, собран, применён на одном экране и ничьих
> тестов не задевает. Применить его к шести адресам — это **повторение
> проверенного**, а не распространение непроверенного.

> **Два разных действия назывались одним словом «распространить»,
> и правило, написанное про первое, тормозило второе.**

Решающим доводом был **`DogEditorScreen`**: черновик локальный `@State`,
сохранения по выходу нет, и единственным выходом с цифровой клавиатуры
было «назад», которое **выбрасывает только что набранный вес**.
В онбординге тот же жест введённое сохраняет. **Кадр `DogStep` про этот
экран не сказал бы ничего**, а человек теряет там данные.

И `PrescriptionEditor` дорог своей причиной: вес, от которого считали
дозу, **не подставляется сам** (решение стоит рядом с полем — рецепт
часто заводят задним числом). Это место, где число вводит только
человек, и потерять ввод значит потерять запись врача.

## Поправка к собственной оценке, найденная в коде

Я называл цену так: «`LabResultEntryFlow` и `LabResultRowEditor`
по три поля, там нужен `enum`». Для второго верно. **Для первого
нет:**

```swift
ForEach($показатели) { $строка in      ← ЦИКЛ, LabResultScreens:346
    …три поля .decimalPad на КАЖДУЮ строку…
}
```

Перечисление из трёх случаев склеило бы «Число» первой строки
с «Числом» второй, а два `.focused` с одним значением дают
неопределённое поведение. Сделано `case число(UUID), нормаНиз(UUID),
нормаВерх(UUID)`; `ЧерновикПоказателя: Identifiable` с `let id = UUID()`
— **проверено, а не предположено**.

> **Померил число полей и сделал вывод о числе случаев перечисления.**
> Та же форма, на которой сосед сегодня чуть не доложил первый пункт
> ревизии: он прочитал `var id: UUID = UUID()` как значение, а это было
> умолчание.

В `LabResultRowEditor` `id` нарочно **нет**: черновик один на лист,
цикла нет, три случая различают однозначно. Разница вписана
в доккомментарии **обоих** перечислений — форма условия названа
по тому, что есть, а не скопирована у соседа.

## Ось для кадра отдана соседу готовым текстом

`projects-c5` получил метод `замеритьПриКлавиатуре` с обратным `guard`,
с числами, объявленными **до** прогона, и с подделкой: вернуть слот
`} bottom: {` вместо `safeAreaInset` — метод обязан покраснеть ровно
на `130` и остаться зелёным на `:368`.

Три вещи в нём сделаны нарочно:

1. **`докрутитьДоКонца()` в нём нет.** У близнеца он есть и правильно;
   здесь он всё портит — человек с поднятой клавиатурой видит
   состояние **до** прокрутки. Это их же четвёртое число приёмки
   («`maxY` при нулевой прокрутке»), и здесь оно единственное годное.
2. **Ось названа внутри самой печати** — после двух величин одного
   имени с обратным знаком число без оси в логе это мина для читателя.
3. **`снять(имя)` без слова НЕГОДЕН** — чтобы годный кадр этого вида
   впервые получил имя, по которому его можно найти. Сейчас все кадры
   с клавиатурой зовутся `…-НЕГОДЕН-клавиатура-поднята`, и поиск
   годного даёт пусто **по устройству имён**, а не потому, что его нет.
